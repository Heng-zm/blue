# MGS v0.1.1

Windows hotfix: the radio now starts and advertises correctly. The previous Windows build stopped at **Starting…** because the app subscribed to a peripheral connection-event stream that the Windows Bluetooth backend does not implement, and the resulting error aborted startup before scanning or advertising began.

## Fixed

- **Windows radio startup** — skip the unsupported peripheral connection stream; scanning and advertising now start normally.
- **Windows discovery** — the radar can now see other MGS devices, and they can see the PC.
- **Windows advertising** — MGS now uses the advertisement published by its registered GATT service instead of starting a conflicting second advertisement publisher. The radio log no longer reports `The parameter is incorrect`, and Settings shows `Advertising · scanning`.
- **Windows radio shutdown** — turning the radio off removes the GATT service so the PC stops advertising immediately.
- Inbound disconnects on Windows are still detected through write/notify failures and the 60-second heartbeat.
- Version bump to `0.1.1` (build 2).

## Upgrade notes

- **Windows and Android users:** replace the old build; v0.1.0 on Windows never opened the radio.
- Both devices must have MGS open at the same time. Windows does not need Bluetooth pairing — MGS connects through its own GATT service.
- iOS builds remain unsigned and require your Apple certificate and provisioning profile.

## Known limitations

- No end-to-end encryption; relays can read messages.
- No store-and-forward; undelivered messages retry for up to 5 minutes.
- Background BLE is best-effort. Keep MGS open for reliable meshing.
- iOS and Windows builds are unsigned. The Android APK uses the Flutter debug signing key.
- BLE requires physical devices; emulators and simulators cannot form a mesh.
